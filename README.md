# IDP Platform

## О проекте

IDP Platform — корпоративное веб-приложение для управления индивидуальными планами развития (ИПР) сотрудников. Система рассчитана на организации от 500+ человек и автоматизирует постановку целей развития, отслеживание прогресса, коммуникацию между руководителем и сотрудником, а также аналитику по развитию персонала.

Три роли с разным уровнем доступа:

- **Сотрудник** — просматривает свои ИПР, обновляет прогресс задач, оставляет комментарии и самооценку.
- **Руководитель** — создаёт и ведёт ИПР для своих подчинённых, оценивает выполнение задач, видит аналитику по подразделению.
- **HR-администратор** — полный доступ: управление пользователями и оргструктурой, справочники, аналитика по всей организации, экспорт отчётов.

## Основные возможности

- Создание ИПР с целями, задачами развития и целевыми компетенциями; жизненный цикл `draft → active → completed/cancelled`.
- Задачи развития с прогрессом, приоритетом, тегами, самооценкой сотрудника и оценкой руководителя.
- Комментарии с Markdown и упоминаниями (@mention) к ИПР и задачам.
- Дашборды для каждой роли: активные ИПР, просроченные задачи, статистика подразделения, охват ИПР по организации.
- Аналитика с графиками (по подразделениям, компетенциям, категориям задач) и экспорт отчётов в XLSX/PDF.
- Управление оргструктурой, справочниками компетенций и шаблонами ИПР.
- Email-уведомления о ключевых событиях (активация ИПР, дедлайны, комментарии, приглашения) через очередь и отдельный воркер.
- JWT-аутентификация (Access/Refresh токены), сброс пароля, выход со всех устройств.

## Технологии

**Backend:** Go, Chi, PostgreSQL 16 (pgx/v5), Redis 7, goose (миграции), golang-jwt, zerolog, viper, go-playground/validator, go-mail.

**Frontend:** React 18, TypeScript, Vite, Zustand, TanStack Query, React Router, shadcn/ui (Radix), Tailwind CSS, React Hook Form + Zod, Tiptap, Recharts.

**Инфраструктура:** Docker Compose, Nginx (reverse proxy, SSL termination), MinIO (файловое хранилище), Mailpit (dev-почта), GitHub Actions (CI/CD).

## Архитектура

Классическая трёхзвенная схема:

```
Browser (React SPA)
      │ HTTPS / REST API
Nginx (reverse proxy, SSL, static)
      │
Backend (Go, Clean Architecture)
      │              │
PostgreSQL         Redis ── Email Worker (SMTP)
```

**Backend** построен по Clean Architecture: `handler → service → repository`, с доменными сущностями в `domain`, DTO для API и зависимостями через интерфейсы (без IoC-контейнеров).

**Frontend** организован по Feature-Sliced Design: `app / pages / widgets / features / entities / shared`.
